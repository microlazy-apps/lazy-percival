# lazy-percival — project context for Claude Code

懒猫微服 (LazyCat MicroServer) lpk wrapper for [Percival](https://github.com/ekzhang/percival).
Upstream Percival is vendored as a git subtree at `vendor/percival/`. **All
adaptations live in `patches/`** — vendor/percival stays pristine.

Build/publish/bootstrap logic is **not** in this repo — it lives in
[microlazy-apps/lazycat-ci](https://github.com/microlazy-apps/lazycat-ci).
This repo just contains caller-specific config + thin workflow wrappers.

## Architecture: single-binary embed

Upstream Percival ships as two pieces:
- a Vite-built Svelte+WASM SPA (the actual app, runs entirely in-browser)
- an optional Go serverless function in `api/` for sharing notebooks via
  GitHub Gists (depends on a `percival-bot` GITHUB_TOKEN, only relevant on
  the public percival.ink deploy)

`patches/01-embed-web-and-dockerfile.patch` rewrites `main.go` to use
`//go:embed all:dist` and serve the SPA on `:8080`, with `/api` gated behind
`ENABLE_GIST_API=true`. Result: one statically-linked Go binary in a
`distroless/static-debian12:nonroot` image. No nginx, no shell, no PID 1
quirks.

The patch also adds a multi-stage `Dockerfile` and `.dockerignore` to
vendor/percival.

## Patches workflow

```sh
# Add a new patch:
cd vendor/percival && vim some/file.go            # 1. modify in working tree
cd ../..
git add -N vendor/percival/<any-new-files>        # 2. let git track new files
git diff --no-color --relative=vendor/percival \
  vendor/percival/ > patches/02-name.patch        # 3. capture diff
git checkout -- vendor/percival                   # 4. restore subtree
rm <any-new-files>
git apply --check patches/02-name.patch \         # 5. verify
  -p1 --directory=vendor/percival
```

CI applies patches in lexical order (`patches/*.patch`) inside lazycat-ci's
docker job before `docker build`, with `--directory=vendor/percival`.

> ⚠️ `git diff` skips untracked files. New files created by a patch must be
> registered with `git add -N` (intent-to-add) before generating the diff,
> otherwise the patch will only contain modifications to existing files.

## Dockerfile cache notes

The Dockerfile is layered for maximum cache hit rate against
`docker/build-push-action`'s `cache-from: type=gha`:

1. **wasm-builder** — `Cargo.toml`/`Cargo.lock` + per-crate manifests are
   copied first and `cargo fetch --locked` runs against a stub source tree
   to warm the registry mount. Real `crates/` arrive next, then
   `wasm-pack build` runs with both registry and target cache mounts.
2. **web-builder** — `package.json`/`package-lock.json` + the npm
   `patches/` (for `patch-package` postinstall) come first, plus the WASM
   `pkg/` (referenced as a `file:` dep in package.json), then `npm ci`.
   Source-only edits never re-trigger npm install.
3. **go-builder** — `go.mod`/`go.sum` + `go mod download` first; sources
   second. `dist/` is mounted in from web-builder.
4. **final** — `distroless/static-debian12:nonroot`. Only the binary moves.

`.dockerignore` strips `node_modules`, `target`, `dist`, `pkg`, `.git`,
`.github`, `.vercel`, IDE folders, and built `*.lpk` from the build context.

## Template architecture

Caller commits `*.template.yml` files with `${VERSION}` / `${LAZYCAT_IMAGE}`
shell-style placeholders. lazycat-ci's `build-lpk.sh` renders them to
`lazycat/{package,lzc-manifest}.yml` (gitignored) via
`envsubst '${LAZYCAT_IMAGE} ${VERSION}'` — only those two vars are
substituted; lazycat's `{{ stable_secret }}` / `{{ .S.BoxDomain }}` /
`{{ .U.* }}` runtime templating is preserved.

- `bootstrap-app.py` reads `package.template.yml` directly for static fields
  (package id / name / locales). For `version`, it reads `os.environ["VERSION"]`.
- `package.yml` and `lzc-manifest.yml` are build artifacts; never commit them.
- `lzc-build.yml` references `./lzc-manifest.yml` — that's the rendered file.

## Lazycat manifest gotchas

- `command:` MUST be a string, not a YAML list. lpk-manager rejects array form.
- Quote any command containing `::` — YAML parses `:` + space as map separator.
- `version` MUST be strict semver. `lpk/read_from_cos` rejects bare SHAs.
  The `prep` job in `release.yml` strips the leading `v` from `${{ github.ref_name }}`.

## Release flow (`v*` tag)

```
git tag v0.1.0 && git push --tags
  ↓
release.yml (caller, this repo)
  ├── prep:   strip leading v -> 0.1.0
  ├── build:  uses lazycat-ci/lpk-build.yml@v0.1.0
  │            apply patches/* to vendor/percival/
  │            docker (ubuntu) -> push ghcr (with tag)
  │            build  (xiaomoru) -> copy-image ghcr->lazycat ->
  │                                  render templates -> lzc-cli project build ->
  │                                  artifact:lpk
  └── publish: uses lazycat-ci/publish.yml@v0.1.0
               publish-release (ubuntu) -> GH Release upload .lpk
               publish-appstore (xiaomoru) -> lzc-cli appstore publish
```

## Bootstrap (first-time appstore submission)

`bootstrap-app.yml` is `workflow_dispatch` with `version` (required) +
`app_id` (optional, skip `/app/create` on retry) inputs. Calls
`lazycat-ci/lpk-build.yml` then `lazycat-ci/bootstrap.yml`. The bootstrap
workflow downloads the lpk artifact and runs lazycat-ci's `bootstrap-app.py`
which performs the 6-API submission flow (login → /app/create → STS+COS →
/lpk/read_from_cos → /upload×N → /app/{id}/review/create).

- `/app/create` returns 500 on duplicate package. Pass `app_id` workflow
  input to skip create on retry.
- Each bootstrap run creates a NEW review record — lazycat does not dedup.
  Manually clean up extra pending reviews in dev center after retries.

## One-time setup (org-level)

- Org/repo secrets `LAZYCAT_USERNAME`, `LAZYCAT_PASSWORD` (done)
- ghcr package `microlazy-apps/lazy-percival` visibility — defaults to PRIVATE
  on first push, must be flipped to Public at
  https://github.com/orgs/microlazy-apps/packages/container/lazy-percival/settings
  (Danger Zone) before lazycat's `copy-image` can pull it.
- Lazycat developer center registration of `cloud.lazycat.app.percival` —
  done via `bootstrap-app.yml`. Re-runnable: pass `app_id` input to skip create.

## Updating percival upstream

```sh
git subtree pull --prefix=vendor/percival \
  https://github.com/ekzhang/percival.git main --squash

# Re-verify the patch still applies:
git apply --check patches/01-embed-web-and-dockerfile.patch \
  -p1 --directory=vendor/percival
```

If the patch breaks against new upstream, edit it (re-derive via the patches
workflow above) before tagging a new release.

## Local lpk build (smoke test)

Requires `lzc-cli`, `envsubst` (gettext), and docker on PATH. Clone
lazycat-ci once and reuse its `build-lpk.sh`:

```sh
# one-time
git clone https://github.com/microlazy-apps/lazycat-ci ~/lazycat-ci

# in this repo:
bash ~/lazycat-ci/scripts/build-lpk.sh \
  --version 0.0.0-dev \
  --docker-context ./vendor/percival \
  --patches-target vendor/percival
# → lazycat/cloud.lazycat.app.percival-0.0.0-dev.lpk
```

For a CI-faithful build (pushes ghcr + lazycat registry), tag a `v*`
release and let `release.yml` run.

## Versioning notes

- Upstream ekzhang/percival has no formal release tags (CI deploys main to
  Vercel). This wrapper picks its own semver starting at `v0.1.0`.
- Bump version on every meaningful upstream pull or patch change.
- Lazycat appstore enforces strict monotonic semver; bumping is required to
  publish.
